Four phases, the workspace-wide layout:

- `1. requirements` — what this module is asked to do.
- `2. design` — [permissions.md](2.%20design/permissions.md), why it is
  shaped this way. It carries what would otherwise be comments in the source.
- `3. implementation` — [todo.md](3.%20implementation/todo.md), the board.
- `4. qa` — how it is tested.
